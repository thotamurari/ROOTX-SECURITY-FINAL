# Security Policy

## Our Commitment to Security

Security is a top priority for this project. We are committed to maintaining a secure, reliable, and trustworthy application. We appreciate the cybersecurity community and responsible security researchers who help us identify and address potential vulnerabilities.

## Supported Versions

Security updates are provided for the latest stable release and actively maintained versions.

| Version | Security Support |
|---|---|
| Latest | Supported |
| Previous versions | Best effort |
| Older versions | Not supported |

## Reporting a Vulnerability

If you discover a security vulnerability, we encourage you to report it responsibly.

**Please do not disclose security vulnerabilities publicly through GitHub Issues or public discussions.**

Instead, report vulnerabilities through:

- **Email:** thotamurari2@gmail.com
- **GitHub:** Contact the repository owner privately.

### Please Include the Following Information

1. A clear description of the vulnerability.
2. Affected component, endpoint, or application version.
3. Steps to reproduce the issue.
4. Proof of Concept (PoC), screenshots, or relevant logs.
5. Potential security impact and severity.
6. Suggested remediation, if available.

## Response and Disclosure Process

We aim to follow a responsible vulnerability disclosure process:

- **Acknowledgment:** We aim to acknowledge reports within 48–72 hours.
- **Investigation:** Reported vulnerabilities will be reviewed and validated.
- **Remediation:** Confirmed vulnerabilities will be prioritized based on severity and impact.
- **Resolution:** Security fixes will be developed and released where applicable.
- **Disclosure:** Public disclosure will take place after the vulnerability has been addressed and coordinated with the reporter.

Response times are targets and may vary depending on the complexity of the issue.

## Scope of Security Testing

Security testing must only be performed on systems, applications, and environments for which you have explicit authorization.

Researchers should avoid:

- Accessing or modifying other users' private data.
- Disrupting application availability or services.
- Performing destructive testing.
- Conducting social engineering or phishing attacks.
- Exposing sensitive information publicly.
- Testing third-party infrastructure without authorization.

## Responsible Disclosure Guidelines

We appreciate responsible security research and encourage researchers to:

- Give us reasonable time to investigate and resolve reported vulnerabilities.
- Avoid public disclosure before a fix is available.
- Share findings privately and securely.
- Provide clear and reproducible technical evidence.
- Stop testing if sensitive data or unintended access is discovered.

## Security Updates

Security fixes and important updates will be published through GitHub Releases, repository commits, and security advisories where appropriate.
